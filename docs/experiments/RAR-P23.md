# RAR-P23 — Windows ABI comparison for the shipped `pext` configuration - `msvc` versus `gnullvm` versus `gnu`. Ad-hoc …

Indexed under *6. Throughput, build and platforms* in [`docs/EXPERIMENTS.md`](../EXPERIMENTS.md).

## Experiment and conditions

**Windows ABI comparison for the shipped `pext` configuration - `msvc` versus `gnullvm` versus `gnu`. Ad-hoc maintainer question outside the roadmap, COMPLETE 2026-09-10, disposition `NO_CHANGE`.** Does building 2.4.0's shipped configuration against a different Windows ABI buy NPS? Toolchain 1.98.1 throughout, host toolchain unchanged; `x86_64-pc-windows-gnu` and `x86_64-pc-windows-gnullvm` added as std targets only (`rustup target add`). MSYS2 `mingw64` gcc 16.2.0 links the `gnu` arm and `clang64` clang 22.1.8 the `gnullvm` arm, the latter matching rustc's own LLVM 22.1.8. Engine source `a927b4d`, which has engine inputs identical to `51d5636` - the one intervening commit is docs-only. Host verified idle at 3-6% `\Processor(_Total)\% Processor Time` before the run. **Two arms, because the `gnu` target cannot be PGO-built at all:** the rustup dist ships no `profiler_builtins` for `x86_64-pc-windows-gnu` (it is present for `msvc` and `gnullvm`), so `-C profile-generate` dies with `E0463 can't find crate for profiler_builtins` before any measurement is possible. **Arm 1, PGO** (`--arch pext --pgo`): 4 independent PGO builds per ABI, pooled because of the ~0.4% per-binary profile-luck offset RAR-P17/RAR-P18 established; `tools/nps_multibuild.ps1 -Cycles 10 -Repeats 3`, readings interleaved with alternating direction. **Arm 2, no PGO** (`--arch pext`): one binary per ABI, since a non-PGO build is deterministic and one binary is therefore the whole population. Every one of the twelve binaries was launched and read **7,601,220 / EBF 2.474** before entering a pool, and all three no-PGO binaries passed `cargo xtask verify-isa --arch pext`.

## Result / disposition

**NO MEANINGFUL DIFFERENCE; `msvc` retained, nothing changed.** PGO arm pooled medians: `msvc` **3,009,192**, `gnullvm` **3,034,419**, delta **+0.84%**, 95% bootstrap CI **-0.12% .. +1.08%** - not resolved. No-PGO arm: `msvc` 2,980,870; `gnu` 2,939,942, delta **-1.37%** CI -2.04..-1.18; `gnullvm` 2,973,873, delta -0.33% CI -0.64..+0.21. **The two arms disagree in SIGN for `gnullvm`**, which is itself the evidence that the effect sits at or below this instrument's floor rather than being a small positive. `gnu` is the one clear result and it is negative: 1.37% slower non-PGO, and about 2.3% behind the `msvc` PGO build once its inability to take PGO is counted - roughly 4-5 Elo at RAR-P02's ~2 Elo per 1% NPS. Incidental, and cross-arm so soft: PGO is worth about +0.9% to `msvc` and +2.0% to `gnullvm` here, so most of `gnullvm`'s PGO-arm advantage is that PGO helps it more, not better baseline codegen. Sizes: PGO 787,968 B `msvc` / 1,152,000 B `gnullvm`; no-PGO 813,056 / 1,407,915 / 1,172,992 B.

## Conditional lesson and retry trigger

**The pool was NOT widened after the result was seen.** Four builds per arm was fixed before measuring; the PGO arm came back at +0.84% with a CI that just includes zero, and enlarging it at that point would be choosing the sample size from the answer. If the question is ever reopened, register 8 builds per arm prospectively. **These artifacts are deliberately not rebuildable from the repository** (maintainer decision 2026-09-10): `build_with_pgo` refuses a non-host target and `asset_name` collapses all three ABIs onto one `target/dist` filename, so the run needed a local patch to `xtask`; the patch was committed, then dropped with this row rather than kept as unused build machinery. Accepted because the disposition is `NO_CHANGE` and nothing downstream consumes the numbers. **Retry trigger:** reopen only if (a) a rustup dist ships `profiler_builtins` for `x86_64-pc-windows-gnu`, making a fair three-way PGO comparison possible for the first time, or (b) B.7's pooled-PGO NPS floor becomes the binding constraint on a search cluster. A toolchain bump alone is not a trigger.
