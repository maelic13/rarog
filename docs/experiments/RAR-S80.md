## Experiment and conditions

**B.3.2 categoricals, four 2,000-game runs — REGISTERED 2026-09-24, before any game.** The zero-game screens (`analysis/b32_screens_2026-09-23.md` §10, choice rule fixed in its preregistration) could not decide four switches of the `b3proof` arm; each is measured as one fixed match on **one tune build**, `tools/test_engines/rarog-b32on-tune-tune.exe` (sha256 `F49E78C9…6D07`, flavor `b3proof-tune`, `cargo build --release --features tune,b3proof` at `3b130c9` clean, bench-verified **7,479,114**), the alternative as arm A by UCI option against the arm's defaults as arm B, so no build offset enters (`colosseum.ps1 -CategoricalTuneBuild`, which records the PGO-gate waiver). Conditions: Colosseum `match-fixed` policy (`3+0.03`, 20 ms margin, Hash 64, Threads 1 restated on both sides, 14 slots, UHO random, no adjudication), 2,000 games each, seeds 20260924–20260927, `-ExpectBench 7479114,7479114 -ExpectRevision 3b130c9`; every dry run resolved to policy with each side's options verified in the resolved configuration. Order: `CoreSingularFloor=1` (donor candidate floor `depth >= 5 + tt_pv`; −11.5% bench nodes, +10 WAC at fixed nodes), `CoreNmpNodes=1` (cut-node NMP; +5.4% nodes, mixed), `CoreProbcutTtServed=1` (Stockfish's TT-served ProbCut; +9.7% nodes, two canaries gained), `SingularTtDepthMargin=2` (RAR-S31's margin; +6.7% nodes, mixed). **Reading rule, fixed here:** an alternative becomes the arm's default only if its run reads **≥ +5 Elo with the 95% lower bound above −5**; between −5 and +5 the default stays and the switch is closed as undecidable at this budget (it remains a switch for B.6); at or below −5 it is closed at the default. Effects are never summed (RAR-S50); if two alternatives are adopted, one further 2,000-game A+B run against the defaults precedes B.3.3's sweep. **Predictions, frozen:** `CoreSingularFloor=1` **+4 ± 10** (fewer nodes per depth, slightly less proof depth); `CoreNmpNodes=1` **0 ± 10**; `CoreProbcutTtServed=1` **+2 ± 10**; `SingularTtDepthMargin=2` **+3 ± 10** (RAR-S31 read +3.35 ± 2.44 on a tune binary before B.2). Whatever is adopted, B.3.3's sweep and SPSA run on the resulting defaults.

## Result / disposition

**Runs 1–2 played 2026-09-24** (`tools/results/b32-cat-singularfloor/`, `b32-cat-nmpnodes/`, both 2,000 games, 0 faults, resolved options verified per side): `CoreSingularFloor=1` **+3.1 ± 9.1 Elo** (W-D-L 519-980-501, pentanomial [27, 235, 464, 241, 33]); `CoreNmpNodes=1` **+3.1 ± 9.3** (499-1020-481, [34, 227, 461, 243, 35]). Both inside (−5, +5): the defaults stay, both closed as undecidable at this budget and left as switches for B.6. Inside the games, nodes per completed depth are equal between the sides (geometric-mean A/B 0.995 and 1.002 over depths 12–18) where `bench 13` moves −11.5% and +5.4%: the bench positions overweight the deep singular chains these switches touch. **Option delivery proven the same day:** a stdin-logging wrapper on each side received, for arm A, `setoption name CoreSingularFloor value 1` then Hash and Threads before `ucinewgame`, and for arm B Hash and Threads only. **Runs 3–4 played 2026-09-24** (`b32-cat-probcuttt/`, `b32-cat-ttdepth2/`, 2,000 games each, 0 faults, recounts equal): `CoreProbcutTtServed=1` **+6.4 ± 9.0 Elo** (517-1003-480, [15, 250, 455, 243, 37]) — meets the rule, **adopted subject to the A+B run**; `SingularTtDepthMargin=2` **+12.9 ± 9.4** (534-1006-460, [30, 217, 442, 271, 40]) — meets the rule with the lower bound at +3.5, **adopted subject to the A+B run**. **A+B run, registered here before it is played:** the pair `CoreProbcutTtServed=1,SingularTtDepthMargin=2` against the defaults, 2,000 games at `3+0.03`, seed 20260928; prediction **+12 ± 10** (not the sum: RAR-S50); rule: A+B ≥ +5 with the lower bound above −5 confirms both as the arm's new defaults; below that, only `SingularTtDepthMargin=2` (the larger single) is baked and `CoreProbcutTtServed` stays a switch. Optional direction check afterwards: `SingularTtDepthMargin=1` against 2, 2,000 games, prediction 0 ± 10. **LTC reads, registered here (maintainer decision 2026-09-24: an LTC gain is a reason to adopt, CCRL's controls being longer than STC):** for each switch left at its default with an STC read ≥ −5 (`CoreSingularFloor=1`, `CoreNmpNodes=1`), one 1,000-game match at **`10+0.1`** (`tools/colosseum/match-fixed-ltc.toml`, margin 20 ms, otherwise the policy; dry run resolved to it), the adopted pair set on both sides, `-CategoricalTuneBuild` on the same tune build; rule: adopt at ≥ +5 Elo with the 95% lower bound above −5, never at an STC read below −5; predictions **`CoreSingularFloor=1` +3 ± 14**, **`CoreNmpNodes=1` +4 ± 14** (the null-move verification region is live only at remaining depth ≥ 16, i.e. at this control). B.3.4 gains a 1,000-game `10+0.1` direction check of the fitted arm against the head as a diagnostic beside its STC gate, never an acceptance rule. **A+B run played 2026-09-24** (`tools/results/b32-cat-both/`, 2,000 games at `3+0.03`, seed 20260928, 0 faults, recount equal, each side's resolved options verified): the pair **+3.6 ± 9.2 Elo** (+6.1 ± 15.2 nElo; 497-1027-476, [25, 253, 421, 278, 23]). Below +5, so by the rule only **`SingularTtDepthMargin=2` is baked** as the arm's default and `CoreProbcutTtServed` stays a switch at 0 for B.6. The bake lands where the run measured it: the `b3proof` consumer alone, as a proof-owned coordinate (the head's path is compiled out on the arm, so the option moved only that consumer); the head's shared `SingularTtDepthMargin` default 3 and its tripwire test are untouched and the off arm stays exact. **LTC reads played 2026-09-24** (`b32-ltc-singularfloor/`, `b32-ltc-nmpnodes/`, 1,000 games each at `10+0.1`, seeds 20260930/20260931, 0 faults, recounts equal, the pair `CoreProbcutTtServed=1,SingularTtDepthMargin=2` on both sides as registered): `CoreSingularFloor=1` **+0.7 ± 12.5 Elo** (241-520-239, [13, 120, 226, 134, 7]); `CoreNmpNodes=1` **−10.4 ± 12.0** (217-536-247, [13, 123, 253, 103, 8]). Neither reaches +5: both stay at their defaults for B.3. The LTC baseline carried `CoreProbcutTtServed=1`, which the A+B rule then declined; that confound cannot turn these reads into an adoption and is recorded, not re-run.

## Conditional lesson

**Calibration:** runs 1–2 predicted +4 ± 10 and 0 ± 10, both inside their bands; the +10 WAC and −11.5% nodes of the floor switch at fixed nodes did not become Elo at `3+0.03`, so fixed-node screens overstate what a population switch is worth in games. Runs 3–4 predicted +2 ± 10 and +3 ± 10; +6.4 inside, +12.9 outside on the good side (a magnitude miss; RAR-S31's +3.35 on the pre-B.2 tune binary was the seed). **A+B** predicted +12 ± 10, read +3.6 ± 9.2: inside the band at its lower edge, but the assumption that the two singles would carry over failed; at ±9 per read, +6.4, +12.9 and +3.6 are all consistent with one common effect near +5, and the registered rule, not the point estimates, decided. **LTC:** `CoreSingularFloor=1` predicted +3 ± 14, read +0.7 ± 12.5, inside; `CoreNmpNodes=1` predicted +4 ± 14, read −10.4 ± 12.0, a sign miss just outside the band: the null-move verification region being live at `10+0.1` did not make cut-node-only NMP pay. Both budgets (±9 at 2,000 games, ±12 at 1,000) resolve only effects of ten Elo or more, which is what they were registered for.
