# RAR-E20 — C.0.3: the full evaluation against the lazy one at equal nodes, so that per-node quality is read apart from tree size and speed

Indexed under *5. Evaluation and data experiments* in [`docs/EXPERIMENTS.md`](../EXPERIMENTS.md).

- **Date / owner:** registered 2026-10-06, before any game; maintainer-run (one fixed match, about 25 minutes).
- **Baseline SHA / candidate SHA / dirty-diff hash:** `dev` at the registration commit; engine source `ee02ed1`, unchanged. No candidate source: both arms are RAR-E19's tune build and differ by one UCI option.
- **Binary / compiler / PGO identity:** `tools/test_engines/rarog-c03-tune.exe` (`cfea92a7…f7e6`, `cargo build --release --features tune` at `7131eb5`, sidecar bench 11,171,726 / EBF 2.512), the binary RAR-E19 played. Side A `LazyMargin=2000` (the full evaluation almost everywhere), side B the default 600.
- **Research question:** RAR-E19 read the full evaluation at **−104.5 ± 10.6 Elo** at `3+0.03`. Speed explains about 11 of it (−5.5% NPS in the games) and the tree at fixed depth grows 8% over 72 game positions (geometric mean 1.06, +22% in middlegames, −12% in endgames; `analysis/artifacts/c03-lazy/tree_d12.txt`). How much of the rest is the search deciding worse *per node* with the full function, and how much is only the time those nodes cost?
- **Hypothesis / proposed mechanism:** most of the loss is per node. Statically the full function is the better predictor above the gate (on `hce-v3-tb/validation.csv` its loss there is 24% lower than the played function's, `full_vs_played.txt`), but it is more extreme by a median 282 cp where the position is already decided (mean |score| 1,504 against 1,141 cp), and the frozen search was fitted against the played function: with the full one its static-to-search residual grows 18% per correction update, aspiration fails low 17% more often, razoring fires 43% more and quiescence delta pruning ten times more. Those are per-node decisions; equal nodes keeps them and removes only the clock.
- **Competing hypotheses:** (1) the loss is time and tree: at equal nodes the full function is near zero or better, and the −104 is the 8% larger tree plus the slower nodes, amplified at this control; (2) the per-node loss is real but concentrated in endgames, where the tree shrinks and the gate fires in most nodes, rather than in the middlegames where the tree grows (not separated by this read; the games' phase mix decides).
- **Interacting mechanisms / consumers:** the static evaluation feeds every pruning margin, the correction history and the TT's stored evaluation; the search is frozen and no coordinate changes. The reading calibrates Phase C's main risk: a statically better evaluation can lose through the search it is fed to.
- **PRE-REGISTERED PREDICTION (freeze before exposure):** Elo of side A (`LazyMargin=2000`) over side B (600) at 150,000 nodes a move.
  - Expected diagnostic movement: none new; the fixed-depth and static readings above were taken before this registration.
  - Expected Elo sign/range: **−70 Elo**, 80% band [−95, −40]. Basis: −104 at equal time less about 11 for speed and about 15 to 25 for the larger tree at this control.
  - Probability positive/useful and confidence basis: probability the read is above −30 (hypothesis 1) 0.10; above 0, 0.03. Moderate confidence: the counter and residual movements are large and one-directional, but no read of this kind exists on this engine.
  - Most likely failure mode: equal nodes is not equal effort when one arm's nodes are more expensive, so a residual time effect survives in the clock-free read through nothing (there is no clock); the more likely miss is magnitude, if the tree's 8% is worth more Elo at `3+0.03` than the 15 to 25 assumed.
- **Falsification criteria:** the hypothesis (per-node loss dominates) is refuted by a read above −30 Elo with its upper bound above 0; a read below −95 says the tree and speed were worth less than assumed and the per-node effect is nearly the whole −104.
- **Cheapest prior falsifier:** the fixed-depth tree read (done): +8% nodes cannot carry −104 Elo, so a per-node mechanism must exist unless this read refutes it.
- **Registered read and stop rule:** one fixed read of 2,000 games, no early stop, no gate: this is an observation of an instrument, it accepts nothing and changes no default (RAR-E19's disposition stands whatever it reads). **Use of the reading, frozen:** if the per-node loss is 40 Elo or more, Phase C treats "statically better, worse in play" as the expected failure mode of a cluster whose evaluation moves magnitudes in lopsided positions, and each cluster's record carries the fixed-depth tree read and an equal-node companion read when its equal-time gate fails, so that a search-mismatch rejection is told apart from a worse function before rule 6 counts it. If the read is above −30, the lesson is the opposite: time and tree size decide at this control, and the screen for a cluster is its fixed-depth tree size and NPS, not its per-node quality.
- **Full conditions / provenance:** `pwsh -File tools/sprt.ps1 -EngineA tools/test_engines/rarog-c03-tune.exe -EngineB tools/test_engines/rarog-c03-tune.exe -NameA lazy2000-nodes -NameB lazy600-nodes -OptionsA LazyMargin=2000 -OptionsB LazyMargin=600 -Mode fixed -Games 2000 -Nodes 150000 -NoAdjudication -Seed 20261008 -ExpectRevision 7131eb5`: fastchess through `sprt.ps1` because Colosseum's run files have no fixed-node mode and RAR-O05 ran its equal-node arm this way; 1T, Hash 64, concurrency 14 with affinity, UHO_Lichess_4852_v1 in random order at the fixed seed, no adjudication, 20 ms margin (irrelevant without a clock). 150,000 nodes a move is about what the head searches per move at `3+0.03` (RAR-E19's games: 132,000 to 138,000).
