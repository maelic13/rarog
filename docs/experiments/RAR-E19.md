# RAR-E19 — C.0.3 lazy path: the played evaluation above `LazyMargin` against the full evaluation, one 2,000-game read with a harm rule

Indexed under *5. Evaluation and data experiments* in [`docs/EXPERIMENTS.md`](../EXPERIMENTS.md).

- **Research question:** does the lazy path cost or gain strength at `3+0.03`, net of the time it saves? Above the gate (`|tapered material + PST + pawns + passer advance| > LazyMargin`, 600) `evaluate` runs the mop-up only and skips the whole piece-activity block (mobility, threats, king safety, hanging pieces, the small terms, the bishop pair) and imbalance (`src/eval.rs`, `evaluate`, the `lazy` branch). The `texel` build disables the shortcut, so every fit (RAR-E06, RAR-E12 and since) describes the full function; above the gate the played function is a different one, and it steps at the gate.
- **Hypothesis / proposed mechanism:** the shortcut was set when the skipped terms were seeded near zero. Fitted, they are piece-value-sized (`imbalance_ours`' queen row reads 3, 107, −98, −63, −130, −97), so in positions with a lopsided material balance the played score is wrong by up to several hundred cp, and the step at the gate reaches the pruning margins and the stored evaluation through the static evaluation. Playing the full function buys that correctness at the measured speed cost; the net is negative but small.
- **Competing hypotheses:** (1) the gated positions are decided, so their score does not change the result and the read is the speed cost alone, about −15 Elo; (2) the step at the gate disturbs static-evaluation-driven pruning and the full function gains more than its cost (a positive read); (3) the speed cost in games is smaller than in `bench`, because games from UHO openings spend a different share of nodes above the gate (not measured: B.8 removed the lazy counters).
- **Interacting mechanisms / consumers:** the static evaluation feeds every pruning margin, the correction history and the TT's stored evaluation (the search is frozen; this changes no search coordinate); the evaluation and pawn caches (unchanged). C.1 moves this code and C.2 generates data with the played evaluation, so this read decides before both.
- **PRE-REGISTERED PREDICTION (freeze before exposure):** Elo of side A (`LazyMargin=2000`, the full evaluation almost everywhere) over side B (600, the head).
  - Expected diagnostic movement (zero games, measured before registration): `bench 13` +3.23% nodes; pooled PGO NPS **−7.52%** (95% −8.74% .. −6.29%; one pool of four PGO tune builds at `7131eb5` on both arms, two interleaved cycles of `bench 13 3`, `tools/nps_read.py`, `analysis/artifacts/c03-lazy/nps-read/`; CPU 13% before the first cycle, above the 5.5% ambient, and both cycles agreed within 1%, so it is not marked disturbed). At about 2 Elo per 1% NPS (RAR-S98) the speed cost alone is about −15 Elo.
  - Expected Elo sign/range: **−8 Elo** (about −13 nElo at this draw rate), 80% band [−20, +4]: the speed cost, partly repaid by correctness in lopsided positions (prior +0 to +10).
  - Probability positive/useful and confidence basis: probability the harm rule fires 0.5; probability of +13 nElo or more 0.05. Basis: the cost read above; no ledger row has measured this margin.
  - Most likely failure mode: the conversion from `bench` NPS to Elo is wrong in either direction, because the speed loss is concentrated in the positions where the gate fires and the games' share of those is not measured.
- **Falsification criteria:** the hypothesis (a small net loss) is refuted by a read at or above 0 Elo with its 95% lower bound above −5 (the correctness side outweighs the cost) or by a read below −25 Elo (the cost is larger than the NPS conversion says).
- **Cheapest prior falsifier:** the zero-game cost read, done: the shortcut buys 7.5% NPS. It bounds the speed side; only games answer the correctness side.
- **Registered read and harm rule:** one fixed read of 2,000 games, no early stop. AGENTS' *Gating*, repair case 2: the standard error is about 7.8 nElo, so side A at or below **−13 nElo is harm** (5% false alarm at a true zero; it catches a true −10 with probability 0.36, −20 with 0.82, −25 with 0.94). **Use of the reading, frozen:**
  - **Harm** (A ≤ −13 nElo): the shortcut stays at 600. C.0.3 continues as research on a repair that keeps the speed (imbalance and the bishop pair, both cheap counts, computed before the gate), registered on its own before any game; C.1 moves the code as it is.
  - **No harm** (A > −13 nElo; a read at +13 or more is recorded as a gain): C.0.3 recommends removing the lazy path, so that the played function is the fitted one, as its own engine commit before C.1, with a new fingerprint. It is accepted on this read if its `bench 13` lies within 0.5% of side A's 11,532,438 nodes (the residual difference is the positions above 2,000 cp of cheap score); otherwise the removal gets its own 2,000-game read.
