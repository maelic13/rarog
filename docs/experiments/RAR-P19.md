## Experiment and conditions

**A.9 (registered as A.3.4 before the 2026-09-10 Phase A reorder) ARM64 compatibility re-verification of the 1.98.1 pin, two hosts, COMPLETE 2026-09-10 (`ef9c6ae`).** Discharges the first of the two obligations RAR-P18 created and did not itself pay. **Hosts:** Surface 7 (Snapdragon X Plus), Windows ARM64, `aarch64-pc-windows-msvc`; and MacBook Air M4, macOS, `aarch64-apple-darwin`. Both checkouts at `ef9c6ae` with `git status --porcelain` empty, so both built the same source as this machine. **Recipe per host, exit status checked directly and not through a pipe:** `rustup show active-toolchain` (1.98.1 auto-installed on both; the `rust-toolchain.toml` override took), `cargo xtask build --arch arm64 --pgo`, `cargo xtask verify-isa --arch arm64 --pgo`, then `bench 13` fed on **stdin** to the finished asset. **x86-64 control on the 5950X:** `cargo xtask build --arch pext` at the same commit, bench by stdin redirect.

## Result / disposition

**ALL GREEN; the `rust-lld` workaround still works on 1.98.1 and all three platforms agree at this head.** **Windows ARM64:** PGO trained, `Merging 1 profile file(s)` accepted, `rarog-v2.3.2-windows-arm64-pgo.exe` linked, SHA-256 `B74755C8...1C2B051F`; ISA contract holds over 127,121 disassembled instructions - prefetch 24, sve/aes/sha2/dotprod 0 against the bare-neon tier baseline. **macOS ARM64:** built `rarog-v2.3.2-macos-arm64-pgo`, SHA-256 `F6390560...ACCA5A15`; contract holds over 167,929 instructions with the same counts. **Fingerprint 7,601,220 / EBF 2.474 / median 145,236 / top-pos 7.2% on all three** (Windows ARM64, macOS ARM64, Windows x86-64 pext), each read from the finished artifact rather than from a training run. Whole-engine NPS, single-run and not an idle-controlled measurement: 1.85 MNPS Snapdragon X Plus, 5.07 MNPS M4.

## Conditional lesson and retry trigger

**Three things this row establishes and one it does not.** (1) RAR-P08's debt is **compiler-versioned, not source-versioned**: the question is whether the pinned toolchain still needs and still honours the `rust-lld` override, so this result survives the 2.4.0 version bump and the branch squash, and the retry trigger is unchanged - re-run on the next pinned bump. (2) **`verify-isa` ran on an ARM64 PGO asset for the first time in the project's history.** RAR-P14 owed this command on 1.97.1 and never paid it, because the tool looked for the non-PGO asset name while the PGO one sat beside it; the fallback added in `2b6d2c0` is what let it run, so `prfm` on the shipped ARM64 PGO binaries is now measured rather than inferred from a hand-check on one M4. (3) The x86-64 control makes **A.3.3 (`79d3974`) bench-neutral on a same-platform comparison** - the ARM64 numbers alone moved platform and commit together and could not have carried that claim on their own. (4) What it does NOT establish: the macOS build is PGO in a weaker sense than the Windows one. `cargo xtask build` sets only `RUSTFLAGS`, and the `cc` crate inherits the PGO flag from those into the C half so both halves of one artifact share a profile; on macOS that inheritance was **rejected** - `warning: Inherited flag "-fprofile-use=..." is not supported by the currently used CC` - while Windows ARM64 printed no such warning. Scope is narrow: `build.rs` compiles exactly one C file, Fathom's `tbprobe.c`, so the cost is Syzygy probe speed on macOS assets and nothing in search, which is consistent with all three fingerprints agreeing. Not release-blocking; **open as a follow-up**, and the trigger to fix it is any work that makes probe throughput matter (D.4). **Two traps recorded because both cost time here.** The assets are named `v2.3.2` and are **not** 2.3.2 builds - they are `ef9c6ae`, the head RAR-E16 measured at roughly +55 Elo over the release - which is the same name-versus-source confusion that nearly voided RAR-E16's baseline; the SHA-256s and the commit above are what disambiguate them. And **the engine ignores `argv`**: `main` goes straight to the UCI loop, so `rarog.exe bench 13` prints the banner and exits at EOF having benched nothing, while an explicit `quit` on stdin kills a bench already dispatched to the engine thread. Feed `bench 13` alone and let EOF close it, which is what `build_test.ps1` does and why it works.
