# C.12 speed pass — overnight record (2026-10-16/17)

PLAN C.12, the behaviour-neutral speed pass on the classical engine, ran
overnight on the maintainer's delegation (the PC free for the night; an SPRT
allowed but not needed, and none was played). Every change reproduces
`bench 13` exactly (**10,521,141 / EBF 2.521**); none changes a node count,
a score or a move.

## Result

**+22.47% pooled-PGO NPS** (95% +21.60% .. +23.34%) for the head
`1108805` against the engine the night started from, `f86a657` (the C.13
head's engine): `bench 13`, PGO pext, one thread, four builds an arm, two
interleaved cycles on a quiet host, read by `tools/nps_read.py` (local
`analysis/artifacts/c12/reads/total3`). The head's engine source is exactly
`b52520d`'s (the last change was reverted), so the read uses that commit's
pool. The first half's head `d2ab515` had read +20.36% against the same base
pool (`reads/total1`), and the chained reads below multiply to +21.6%, in
agreement within their intervals.

The gate is registered as RAR-S99 (`docs/experiments/RAR-S99.md`):
`tools/test_engines/rarog-c12speed-pext-pgo.exe` (SHA-256 `C689367B…`,
`a829601`: the head plus two exact cleanups, clean, bench 10,521,141,
sidecar beside it) against `rarog-c13best-pext-pgo.exe` (`3C92DC47…`,
`931dcca`, the same bench). The two binaries read +22.58% apart directly
(median of six alternating benches each). **RAR-S99 accepted H1 at 875
pairs: +42.3 ± 9.5 Elo, +73.2 ± 16.3 nElo at `3+0.03`**, with +23.6%
nodes a second and +0.60 plies inside the games; the frozen prediction was
+42 Elo, 80% band [+30, +55].

## Method

- **Profile first.** The maintainer's elevated ETW capture (`bench 13 5` and
  six replayed games at 150,000 nodes a move, `tools/profile_etw.ps1`,
  extended for it in `55f0e11`) located the time (bench / games): evaluation
  25.9 / 26.8%, move ordering 20.3 / 20.1%, the node body 13.0 / 13.4%,
  generation 8.6 / 8.4%, TT 8.4 / 8.0%, make/unmake 6.8 / 6.8%, SEE
  6.6 / 5.8%, evaluation correction 4.6 / 4.1%, history updates
  3.6 / 3.8%. Later profiles came from a user-mode sampler written tonight
  (suspends the engine thread about 1,000 times a second and symbolizes the
  instruction pointer with full inline chains; no administrator rights).
- **Micro-benchmarks** for isolated parts, each checked by a checksum of its
  results: evaluation only (81,580 game positions, 12% of them repeats;
  344 ns per call at the baseline, 242 ns at `d2ab515`, which no longer
  caches the repeats), SEE (543,851 move cases), perft. These are built
  with the pext flags of the gate binaries
  (`--cfg rarog_pext -C target-cpu=x86-64-v3 -C target-feature=+bmi2`);
  a plain `cargo build` has neither POPCNT nor PEXT, reads 15% (baseline)
  to 47% (head) slower and is not comparable. The same split applies to
  the generic x86-64 release asset: built that way the head's evaluation
  is 10.6% faster than the baseline's (355 against 397 ns), against 30%
  with the pext flags, because the set counts lean on POPCNT.
- **Screens rank, reads decide.** A non-PGO alternating bench screen (noise
  about ±0.4%), then a two-build PGO screen, then the recorded four-build
  pooled read with PROCESS's two-step rule. Several changes read differently
  with and without PGO (below), so from 00:30 every candidate was screened
  with PGO.
- **A read is taken with the host quiet.** Two late screens were flagged
  disturbed while this session was issuing commands, and a repeat with the
  session idle read both arms 2–3% higher (`screens/qttlate-read2`). The
  final reads ran with the session idle.

## What changed, and why it is exact

Evaluation:

- `1781b34` — the weights and the material/PST tables are compile-time
  constants in production builds (zero-sized handles deref to statics), so
  each weight folds into the code reading it. `tune`, `texel` and unit tests
  keep runtime weights.
- `6420bd5` — the imbalance sums each row before its count multiplies it; a
  type a side lacks multiplies by zero, so the skip branch was only a
  branch. Screen +1.6%.
- `7f3f81e` — threat and hanging terms count victims per type by set
  intersection instead of walking squares and decoding the mailbox; integer
  sums are order-free. Screen +4.9%: the largest single eval change.
- `b6b32ba` — past five men without a bare king only the opposite-bishop
  scale can apply; the other recognisers are skipped (debug-asserted).
- `e9f962a`, `25a7126` — outposts, rook files, queen infiltration, blocked
  passers and rooks behind passers as set counts.
- `154fc9d` — the pawns' material and squares live in the pawn entry.
- `523a711` — the imbalance is cached by the piece counts (40-bit
  signature, 1,024 slots). Screen +1.6%.
- `0f745eb` — the whole-evaluation cache is gone: on bench it served 966 of
  4,112,440 calls (the TT already stores every raw eval) while its lookup
  missed the caches on every call. PGO screen +0.8%.
- `5a56679` — passed-pawn stop and path safety from one enemy attack set
  per side, built on first need (symmetry of the attack relation;
  debug-asserted). PGO screen +0.6%.

Search, ordering, board:

- `d61d4f6` — the per-node search parameter sets (core, proof, quiet) are
  compile-time constants outside `tune` builds; `d2ab515` keeps the root,
  clock and quiescence set (`SearchParams`) runtime, because the zugzwang
  integration test sets one of its switches (the debug assertion caught it;
  the fix costs nothing measurable, +0.03%).
- `081041c` — **the best-move selection uses `select_unpredictable`.** The
  PGO build had laid the selection's comparison out as a branch, which
  mispredicts at every new maximum. Non-PGO screen +0.1%, **PGO +3.9%** and
  +4.24% recorded: the largest single change of the night.
- `58547cd` — pawn and knight attack sets of whole sets by shifts (the
  tables are built from the same functions), in `Board::threats` and the
  quiet ordering context. Screen +1.7%.
- `acd767e` — make/unmake toggle the pawn, minor and non-pawn keys by a
  mask per piece type instead of matching it. Screen +1.3%.
- `09bb98c` — a one-kind generation pass knows its move flag statically.
- `60f8b96` — quiescence passes a known check status to the make.
- `1aaa39e`, `65f490e` — the child's TT line is prefetched when the move is
  picked, ahead of the pruning tests. PGO +0.5% and +0.3%; moving the
  prefetch later or dropping it lost 1.7%.
- `9f388c5` — staged king moves are decided from the node's threat set
  (`threats.all` is exactly the squares the king may not enter;
  debug-asserted).
- `b52520d` — **the attack tables are built at compile time.** They lived
  behind a `LazyLock`: every lookup checked that the tables existed (0.6% of
  the profile's samples sat on that check alone) and loaded the slider
  table's heap pointer before the entry. `ATTACKS` is now a plain static with
  fixed-size slider tables, so a lookup reads a fixed address. The magic
  layout is built from the baked magics, and a magic that sent two attack
  sets to one slot would stop the build, so the runtime search for a
  replacement magic is gone. The exhaustive slider test passes on the PEXT
  and the magic backend, and both bench 10,521,141. The executable grows
  from 1.01 to 1.85 MB. PGO screen +2.36%; recorded read e8 +1.46%.

No new `unsafe`; no change to the unsafe floor. The search-side commits are
behaviour-neutral under the search freeze and are listed in D.3's change
log.

The five screens from the SEE attackers to the SEE fast path were read
against the same two-build pool of `c8934ec`; a pool that happened to read
high would bias all of them down by a few tenths, so each is "not shown",
not "shown to cost". The SEE fast
path is the best of them: its 28% hit rate predicts about +0.5%, which a
four-build read with six cycles could resolve. The pawn entry is the
night's measured warning against two-build screens: +1.06% there, +0.02%
with four builds an arm on a quiet host.

Lessons for later passes: screen branch-shape and prefetch changes with PGO
(non-PGO ranked `081041c` at +0.1% and it read +4.2%; the pick-time prefetch
read −0.04% without PGO and +0.5% with it; the passer attack set showed
nothing in the eval micro-benchmark and +0.6% in the PGO screen). Indirection
that the compiler cannot see through was the night's best late find
(`b52520d`); the slider lookups themselves are cheap enough that reusing
filled attack arrays does not beat them; the history and TT costs are memory
latency that prefetching did not buy back. A two-build PGO screen resolves
about ±1.5%; below that, changes need four builds an arm.

## Verification

- Every engine commit built and benched at 10,521,141 before it was
  committed.
- On the head `1108805`: the debug suite (32 test binaries, 395 tests) and
  the release suite (396; one fuzz test runs in release only) pass with
  none failed, the allocation guard included; `cargo clippy --all-features
  --all-targets` reports zero warnings and `cargo fmt --check` is clean; the
  `tune` and `texel` builds and the excluded texel tuner build (local
  `analysis/artifacts/c12/final2/`).
- New debug assertions check each shortcut against the computation it
  replaces (endgame dispatch, passer attack set, king legality, generation
  flag, the compiled-in search sets).
- `b52520d` was checked on both slider backends: the exhaustive slider test
  and `bench 13` on the PEXT and the magic build. The `--cfg rarog_pext`
  clippy configuration had three errors and two warnings in
  `src/board/attacks.rs` that predated the night (the same at `f86a657`);
  `e55dc9e` fixes them, and clippy is clean in both configurations.
- Found on the way and fixed: `nps_build_pool.ps1` wrote `(clean)` into
  every manifest, dirty pools included, and could not see an edit made
  while a pool compiled (the e2 pool was rebuilt for that). `a829601` reads
  the tree again after the builds, labels a dirty or changed pool DIRTY and
  refuses one asked to be clean.

## The gate: RAR-S99

C.12's contract needs no games (an exact fingerprint means unchanged
behaviour, and RAR-S98 prices speed at about 2 Elo per 1%), but the
maintainer asked for a final gate, and RAR-S99 registers it with RAR-S98's
design, which stopped at H1 in 1,051 pairs: `sprt-default` (`[0,3]` nElo),
a 5,000-pair cap, UHO in random order, `3+0.03`, Hash 64, one thread, seed
20261017. H1 confirms the pass in games and nothing more is played. The
frozen prediction is +42 Elo, 80% band [+30, +55].

- Candidate: `tools/test_engines/rarog-c12speed-pext-pgo.exe` (`C689367B…`, `a829601`).
- Baseline: `tools/test_engines/rarog-c13best-pext-pgo.exe` (`3C92DC47…`, `931dcca`).
- Both bench 10,521,141, so the gate measures speed alone. Each arm is one
  PGO build, so a build's own offset (about ±1%, from the pools' spread)
  rides on the reading.
