# D.7.8.12: where the compact kernel spends its time — profile, 2026-11-20

The input to PLAN D.7.8.12, the speed pass before D.7.9 and the fit
(maintainer decision 2026-11-20: as much effective speed and NPS as can be
had before the work continues, Reckless as the reference). Zero games; no
engine source changed. The evidence layer is CPU samples and nanoseconds a
node, which are not NPS reads and not Elo.

## Method

- **Rarog:** the shipped form, a pext PGO build of `63fa0e2` (engine source
  `b88700a`) by `cargo xtask build --tier pext` with
  `CARGO_PROFILE_RELEASE_DEBUG=2` (debug information lives in the PDB and
  does not change code generation: the binary is byte-identical to the dist
  build of the same tree, SHA-256 `b06982fd…d015`). `bench 13` 3,320,355 /
  EBF 2.317, **2,407,799 nps, 415 ns a node** undisturbed.
- **Reckless:** `0756957` with the later tablebase fix (`8d7d1dd`), its
  network `v60-7f587dfb`, built `--no-default-features` (no Syzygy: the
  local clang lacks the MSVC headers Fathom needs), `target-cpu=native`, no
  PGO, debug information on (SHA-256 `d7edb5cb…b441`). Its `bench`:
  2,837,905 nodes, **1,224,202 nps, 817 ns a node**. The missing PGO costs
  it a few percent; the comparison below is read per component, never as a
  total.
- **Sampler:** C.12's user-mode sampler (`analysis/artifacts/c12/
  sampler_args.py`, about 800 samples a second, the instruction pointer
  only), symbolised with inline chains by `llvm-symbolizer`; a sample is
  counted at its leaf, and by module at the innermost engine module of its
  chain (`analysis/artifacts/d7812/modules.py`). Host idle (1.8% CPU, no
  engine or build running).
- **Workloads:** `bench 13`, 20 runs, 32,702 samples; game play by
  `tools/profile_games.py`, 12 games of RAR-S132's PGN at 150,000 nodes a
  move with the hash carried, 1,530 searches, 134,025 samples (through
  `analysis/artifacts/d7812/sampler_games.py`, the same sampler attached
  to the driver's engine); Reckless's `bench`, 12 runs, 34,973 samples.
  Outputs in `analysis/artifacts/d7812/` (ignored).

The two Rarog workloads agree to within a point everywhere (the table 9.1%
of samples in bench and 9.9% in games), so bench, the PGO training load,
stands for game play here.

## Against Reckless, a component at a time

Nanoseconds a node, by the innermost module (Rarog bench at 415 ns a node,
Reckless at 817):

| Component | Rarog | Reckless |
|---|---|---|
| Evaluation | ~95 (HCE) | 393 (NNUE) |
| Transposition table | **48** | **23** |
| Board, bitboards, attacks, generation | ~120 | ~140 (board, bitboard, lookup, setwise, square, piece) |
| Picker and histories | ~33 (picker module, histories) plus the kernel's scoring | 95 (movepick 51, history 44) |
| Search node and rules | ~114 (`search::compact` and `Searcher`) | ~60 (search, stack, qsearch, make) |

Module boundaries differ between the engines (Rarog's quiet scoring sits in
`search::compact::rules`, Reckless's in `movepick`), so only the table's row
is a like-for-like read. Outside the evaluation Rarog is about as fast a
node as Reckless; the one component where Reckless is clearly faster is the
table, and its probe shows no stall line at all (its hottest table line
0.09% of samples, against Rarog's 8.51% on one load).

**Why:** Reckless prefetches the child's table cluster *before* it makes the
move, from the key the move will produce (`td.board.key_after(mv)`,
`search.rs` `make_move`), and again after; the make, the stack writes and
the network's push run while the line arrives. Rarog prefetches only after
`make_move` (`node.rs`, `quiescence.rs`), and the child probes almost at
once, so the load stalls. Rarog has the hint already: `Board::key_after_hint`,
exact for a plain move or capture, tested, and unused by the compact
kernel.

## Candidates

Each behaviour-neutral unless marked; the share is the profile's ceiling,
not a prediction.

1. **The table prefetch before the move** (Reckless's form): prefetch
   `key_after_hint(mv)` before the push and the make in the node, in
   quiescence and in ProbCut, keeping the prefetch after. Ceiling about
   8.5%.
2. **The correction and pawn-table entries prefetched** (Rarog's own): the
   three correction slots and the pawn entry are known after the make, and
   the table probe sits between the make and the evaluation. Ceiling about
   3.4%.
3. **`SearchedMoves` without its per-node writes:** storage written only as
   moves are pushed, through one shared fixed-capacity list type, so no new
   `unsafe` site (the floor is 17). Ceiling about 0.7%.
4. **The board's undo stack as a fixed array** indexed by its length, no
   `Vec` capacity checks. Ceiling about 0.65%. Board code, which D.12
   rebuilds later; this is the stack alone.
5. **The evaluation's hot paths** (`eval_piece_activity`, `eval_threats`,
   `AttackMaps::fill`, the slider lookups they make): a drill on the
   lines, behaviour-neutral rewrites only; the evaluation is 21 to 23%.
6. **Quiet scoring** (4.4% plus the 2.6% multiply): the cost is the
   continuation-history loads, which Reckless pays the same way; nothing
   neutral is evident, so it is examined, not presumed.
7. **Selection and tie order (behaviour-changing):** a different selection
   step for the quiets would move the tree (the root's tie order alone moved
   it by a third, D.7.8.3) and needs its own game read; listed, not
   recommended.

Not candidates: the release profile already matches Reckless's (`lto =
"fat"`, one codegen unit, `panic = "abort"`); the PGO training load is
`bench 13`, which the game profile matches.

Each item a commit at `bench 13` 3,320,355 / EBF 2.317, read by PROCESS's
pooled method (four pext PGO builds an arm, `tools/nps_read.py`) against the
commit before; the reads are in `analysis/artifacts/d7812/nps/`.

| Item | Commit | Read | Outcome |
|---|---|---|---|
| 1, the table hint before the make | `1ff6522` | +1.09% (+0.52 to +1.67) | accepted |
| 2, the correction and pawn entries | `8f3c0f0` | +0.14% (−0.16 to +0.44), six cycles | `NO_CHANGE`, reverted (`2aad651`) |
| 3, one fixed-capacity list | `80cef6f` | +0.31% (+0.04 to +0.57), six cycles | `NO_CHANGE`, kept: removes code and work, adds none |
| 4, the undo stack | — | — | not built: a game's history is unbounded |
| 5, the evaluation | — | — | none: no line above 0.5% |
| 6, quiet scoring | — | — | none: the loads are the donor's own |
| 1b, the table hint where the move is picked | `0690de9` | +1.12% (+0.93 to +1.31) | accepted |
| **The pass** | `0690de9` against `b88700a` | **+2.71% (+2.11 to +3.31)** | accepted at step 1 |

Item 2's first two reads were discarded as the method requires (four and
one disturbed cycles): the host's level moved by 1.5 to 2.5% while a
remote-desktop session was opened and closed during them; the third, with
no session change, was clean. A session held steady through a read does not
disturb it, since the arms alternate; a session opened or closed during one
does.

A profile of items 1 and 3 (`analysis/artifacts/d7812/prof2/`, 30,692
samples) put the probe at 6.09% of samples and 5.5% on the cluster's first
load, down from 9.12% and 8.5%, which is why item 1b was tried.

The assembly of the final state (`cargo rustc --release --lib -- --emit=asm`)
holds no `memcpy` or `memset` in `compact_negamax`, `compact_quiescence`,
`CompactPicker::next`, `make_move_inner` or `Evaluator::evaluate`; the
profile has no sample in a clone or a drop, 0.01% in `memcpy` (outside the
search) and 0.79% in the board's undo `Vec` push and pop.
